- 2026-10-08 · **PT-7 · Packaging. Mechanism settled by documentation; plugin deferred, skip recorded.** The question open twice was whether Cowork loads a repo's `.claude/skills/`. It does not. Anthropic's own skills documentation states that Cowork sessions and cloud sessions do not read `~/.claude/skills/`, and that both interactive and scheduled Cowork sessions load the skills enabled for your claude.ai account, synced at session start. The same page says cloud sessions additionally load project skills committed to the cloned repository's `.claude/skills/`, and it names only cloud sessions there, not Cowork. So project skills reach the local terminal and the Code tab and cloud sessions, and reach Cowork only by way of the account. Read at `https://code.claude.com/docs/en/skills`, verified 2026-10-08. The upstream feature request for project-scoped skills in Cowork, `anthropics/claude-code#60205`, was closed as **not planned** on 2026-07-20 after going stale, so this is settled rather than pending. That also explains the 2026-09-22 observation that muddied this: `pm-design-check` surfaced in Cowork as `anthropic-skills:pm-design-check`, and `anthropic-skills` is the namespace Claude Code reserves for skills synced from claude.ai. By inference, not by direct read, the skill reached that session through the account sync and not from the repo. **Decision: the four `pm-` skills stay in `.claude/skills/` and the plugin is not built.** Where the gates actually run is the harness on every edit, the pre-commit hook, and CI, and all three read the repo. A plugin would buy Cowork coverage and cross-machine installability, since Anthropic's Cowork documentation says a plugin added to an account works in chat and Claude Code as well as Cowork. Neither is needed today, and `CLAUDE.md` already reaches every surface, which is the doctrine layer that matters most in Cowork. Revisit if someone outside this repo needs the skills, or if prose starts being drafted in Cowork. Two known bugs still temper the plugin route: a committed `enabledPlugins` does not prompt to install on first clone, and Cowork has an open issue loading only some user-level skills.
